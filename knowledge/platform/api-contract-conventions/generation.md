# How the published document is produced

The **normalized OpenAPI document is generated by the fixed, deterministic
pipeline, and it is the only OpenAPI document any consumer reads.** Nothing
reads the framework's raw output.

The ordering matters more than the individual steps. Each stage assumes the
previous one has already run, so the sequence is a contract rather than a
preference — reordering it produces a document that is still valid and no longer
deterministic.

## Why determinism is the point

A generated document that varies between runs cannot be diffed, and a document
that cannot be diffed cannot gate anything. Determinism is what turns generation
into a **check** rather than a build artifact somebody regenerates when it
disagrees with them.

So the pipeline is a gate. It fails on a duplicate or missing operation
identifier, a request body on a method that must not carry one, an example that
does not validate against its own schema, non-deterministic output, and drift or
an unapproved breaking change.

Treat a failure here as a contract problem, never as a generator problem to be
worked around by editing the output.

## Generated material is never hand-maintained

Everything downstream is generated from the same authored sources: the
documentation UI, the committed document, compatibility checks, the generated
client, the tool surface, the runtime metadata answers, and generated reference
prose.

Because they share a source, they cannot disagree. Hand-editing any of them
reintroduces exactly the second description the authoring rule forbids, with the
additional problem that it now looks authoritative.

The runtime metadata answers are the case most often mistaken for a place to
"just add a field". They are generated from the authored schemas, the operation
catalog, and the per-module projection configuration — never from a catalog
maintained beside them.

## What this concept does not carry

The generated document itself, and any route it contains. Reproducing it here
would create the second source this module exists to forbid, and would go stale
the first time the contract changed.
