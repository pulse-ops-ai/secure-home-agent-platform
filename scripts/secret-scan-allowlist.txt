# Allowlist for scripts/scan-secrets.sh
#
# THE ONLY suppression mechanism. There is no sentinel comment, no in-line
# pragma of any spelling, and no file-level exclusion — see the header of
# scripts/scan-secrets.sh.
#
# FORMAT — one entry per line, all parts required:
#
#     path:line:sha256=<64 hex digits> # justification
#
# The finding is identified by a digest of the exact line content, never by the
# value itself. That is deliberate: this allowlist is a tracked file and the
# scanner scans it, so pasting a credential here would create a finding — or,
# worse, a place to hide one. It also makes an entry self-invalidating: change
# the line and the entry stops applying, forcing re-review instead of silently
# covering new content.
#
# You do not compute the digest by hand. When the scanner reports a finding it
# prints the exact line to add:
#
#     FINDING docs/example.md:42:...
#             to allowlist, add: docs/example.md:42:sha256=<digest> # <why this is safe>
#
# (This file is scanned like any other. If a line you write here trips the
# scanner, reword it — do not allowlist the allowlist.)
#
# ENFORCED — validated in code, not merely requested. Any violation aborts the
# scan with exit 2 *before scanning*, so a broken allowlist can never read as
# "no findings":
#
#   * entries under .github/workflows/ are rejected outright — workflows are the
#     highest-consequence place for a credential to leak, and they define
#     execution permissions;
#   * path-only and whole-file entries are rejected (the three-part structure is
#     required);
#   * wildcards in a path are rejected;
#   * a path that is not a tracked file is rejected, so stale entries must be
#     removed rather than accumulating;
#   * a digest that is not exactly 64 lowercase hex digits is rejected — no
#     prefixes, no truncation;
#   * a missing or short justification is rejected.
#
# Matching is exact on path, line number, and content digest. An entry cannot
# suppress a finding on any other line, in any other file, or on the same line
# after its content changes.
#
# Prefer fixing the finding over allowlisting it. An obviously-fake placeholder
# ("replace-me") does not trip the scanner; a realistic-looking one does, and
# that is the scanner working correctly.
#
# Currently empty: there are no false positives, because there are no
# credential-shaped values in this repository at all.
